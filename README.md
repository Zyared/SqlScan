# SqlScan

Десктопное Windows-приложение для обнаружения SQL-инъекций в тексте. Анализирует строку или файл по набору сигнатур, выставляет вес опасности и формирует цветной отчёт.

> [!NOTE]
> **Идёт обновление до версии 2.0.** Главное в новой версии — рабочая база данных: сигнатуры редактируются без пересборки, каждая проверка сохраняется в журнал, есть статистика. Также добавятся построчный анализ журналов, защита от простых обходов и измеренная точность обнаружения на независимых данных.
>
> - Полное техническое задание: [`docs/TZ_SqlScan_2.0.md`](docs/TZ_SqlScan_2.0.md)
> - Стабильная версия 1.0 — тег [`v1.0`](https://github.com/Zyared/SqlScan/tree/v1.0). Ниже описано её текущее состояние.

### Как развернуть базу SqlScan 2.0

1. Установите сервер PostgreSQL и утилиту `psql`. Для подключения из Windows-приложения x64 понадобится 64-разрядный драйвер psqlODBC Unicode. [PostgreSQL для Windows](https://www.postgresql.org/download/windows/) · [psqlODBC](https://odbc.postgresql.org/).
2. Войдите в `psql` как администратор PostgreSQL. Следующие команды создают отдельную базу и роль. Команда `\password` запросит пароль интерактивно.

   ```sql
   CREATE ROLE sqlscan_app LOGIN;
   \password sqlscan_app
   CREATE DATABASE sqlscan ENCODING 'UTF8' TEMPLATE template0;
   \connect sqlscan
   REVOKE CREATE ON SCHEMA public FROM PUBLIC;
   CREATE SCHEMA sqlscan AUTHORIZATION sqlscan_app;
   ```

3. Из корня репозитория выполните в PowerShell команды ниже. Скрипт создаёт шесть таблиц в схеме `sqlscan`, загружает 18 действующих сигнатур из версии 1.0 и задаёт порог 5. Повторный запуск сохраняет изменения правил, настроек и журнала.

   ```powershell
   $env:PGCLIENTENCODING = 'UTF8'
   psql -X -h localhost -U sqlscan_app -d sqlscan -v ON_ERROR_STOP=1 -f db/schema.sql
   psql -X -h localhost -U sqlscan_app -d sqlscan -c "SELECT count(*) FROM sqlscan.rule WHERE enabled"
   ```

4. Для этапа интеграции с GUI откройте «Источники данных ODBC (64-разрядная версия)». Создайте пользовательский DSN `SqlScan`, выберите драйвер PostgreSQL Unicode x64, укажите сервер, порт, базу `sqlscan` и пользователя `sqlscan_app`. Проверьте соединение кнопкой **Test**. Текущая версия GUI читает правила из встроенного набора.

В журнале `scan` хранятся SHA-256 в виде 32 байт, размер ввода и порог на момент проверки. Каждая строка `hit` сохраняет текст сигнатуры, вес, признак высокого риска и до 200 символов контекста. Номер строки начинается с единицы, позиция — смещение в байтах UTF-8 от начала нормализованной строки, с нуля. При удалении проверки её совпадения удаляются вместе с ней.

Для проверки повторите создание базы и схемы из шага 2 с именем базы `sqlscan_test`, используя уже созданную роль `sqlscan_app`. Оставьте схему пустой. Скрипт ниже проверяет ограничения, сохранность истории и повторную инициализацию, затем откатывает тестовую транзакцию.

```powershell
$env:PGCLIENTENCODING = 'UTF8'
psql -X -h localhost -U sqlscan_app -d sqlscan_test -f db/test_schema.sql
```

## Текущая версия 1.0

### Возможности

- Ввод текста вручную или загрузка из файла (до 2 МБ)
- 18 паттернов SQL-инъекций с весами от 1 до 5
- Цветовой градиент результата: зелёный → жёлтый → красный
- Подсветка опасных фрагментов в нормализованной строке
- Сохранение отчёта в файл UTF-8
- Динамическое изменение размера окна

### Как работает детектор

1. Входная строка **нормализуется**: приводится к нижнему регистру, несколько пробелов схлопываются в один
2. По нормализованной строке ищутся все **паттерны** из таблицы правил
3. За каждое вхождение к сумме прибавляется **вес** паттерна
4. Если найден хотя бы один паттерн с пометкой «высокий риск» или сумма весов ≥ 5 — строка считается **подозрительной**

### Таблица паттернов

| Паттерн | Вес | Высокий риск |
|---------|-----|--------------|
| `' or` | 3 | да |
| `" or` | 3 | да |
| `or 1=1` | 4 | да |
| `1=1` | 2 | нет |
| `;` | 1 | нет |
| `--` | 3 | да |
| `/*` | 2 | нет |
| `*/` | 2 | нет |
| `;--` | 4 | да |
| `union select` | 5 | да |
| `sleep(` | 4 | да |
| `benchmark(` | 4 | да |
| `xp_cmdshell` | 5 | да |
| `information_schema` | 3 | нет |
| `drop table` | 5 | да |
| `insert into` | 3 | нет |
| `update set` | 3 | нет |
| `delete from` | 3 | нет |

В версии 2.0 эта таблица переезжает в базу данных и станет начальным набором правил.

### Требования

- Windows 10 / 11
- Visual Studio 2022 (с компонентом «Разработка классических приложений на C++» и поддержкой MFC)
- Windows SDK (устанавливается вместе с Visual Studio)
- Для 2.0 дополнительно: PostgreSQL и ODBC-драйвер psqlODBC x64 (см. «Как развернуть базу SqlScan 2.0»)

### Сборка

1. Открыть `SqlScan.slnx` в Visual Studio
2. Выбрать конфигурацию `Debug` или `Release`, платформу `x64`
3. `Build → Build Solution` (или `Ctrl+Shift+B`)
4. Готовый `.exe` находится в папке `x64\Debug\` или `x64\Release\`
