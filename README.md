# SqlScan 2.0

Windows-приложение на C++20 и MFC для построчной проверки текста и журналов по SQL-сигнатурам. PostgreSQL хранит правила, результаты и историю совпадений. База доступна через ODBC.

Сборка для перепроверки включает исходный код, тестовый runtime, независимый пересчёт баллов и сценарий `Recheck.cmd`. Полный эксперимент с пятью источниками запускается командой `Recheck.cmd -Quality`. [Матрица соответствия требованиям](docs/VERIFICATION.md).

## Запуск готовой сборки

Установите MSI для текущего пользователя и откройте SqlScan из меню «Пуск». В переносном варианте распакуйте комплект Windows x64 и запустите **SqlScan-Local.cmd**. Он подготовит локальный PostgreSQL, подключит приложение и сохранит журнал между запусками. **SqlScan.exe** можно запускать отдельно для автономного анализа или подключения к своей базе. Для первой проверки откройте `examples/demo.log` и нажмите **Проверить**.

## Возможности версии 2.0

| Вкладка | Действия |
|---|---|
| Проверка | Ручной ввод или файл, построчная оценка, нормализация, категории, четыре уровня риска, цветная подсветка, экспорт TXT/CSV/HTML |
| Журнал | Поиск и фильтры, сортировка, страницы по 50 записей, просмотр и экспорт архивного отчёта или выборки, удаление проверки |
| Сигнатуры | Добавление, редактирование, отключение и удаление, восемь категорий, применение изменений при следующей проверке |
| Статистика | Число и доля подозрительных проверок, диаграмма по дням и десять самых частых сигнатур |

Без соединения используются 18 встроенных правил. При настроенном подключении приложение сохраняет проверку и совпадения в одной транзакции. Для файла с уже известным SHA-256 можно открыть прошлый отчёт. Пакетный режим `--batch` выдаёт CSV с предсказаниями для размеченных данных.

## Сборка и тесты

Для сборки установщика из готового комплекта используйте Python 3.11+ и WiX 3.14.1: `python deploy/build_installer.py <комплект> <каталог-WiX> SqlScan-2.0.1-x64.msi`. Сценарий сверяет SHA-256 каждого упаковываемого файла.

Используйте Visual Studio 2026, MSVC v145 x64, MFC и Windows SDK. Откройте `SqlScan.slnx` и соберите `Release | x64`. В x64 Developer PowerShell доступны те же исходники и отдельный сценарий сборки.

```powershell
.\build-release.ps1
.\tests\run.ps1
python tests/batch_smoke.py x64/Release/SqlScan.exe
```

Проект `tests/NativeTests.vcxproj` добавляет проверки в Test Explorer. Для тестов репозитория БД задайте переменную процесса `SQLSCAN_TEST_CONNECTION` со строкой ODBC отдельной тестовой базы. Для проверки GUI дополнительно нужны Python, pywinauto и pywin32. Команды и результаты приведены в протоколе испытаний.

## Внешняя база PostgreSQL

Для собственной базы установите PostgreSQL и 64-разрядный драйвер psqlODBC Unicode. [PostgreSQL для Windows](https://www.postgresql.org/download/windows/) · [psqlODBC](https://odbc.postgresql.org/).

Пример подготовки отдельной базы администратором через `psql`:

```sql
CREATE ROLE sqlscan_app LOGIN;
\password sqlscan_app
CREATE DATABASE sqlscan ENCODING 'UTF8' TEMPLATE template0;
\connect sqlscan
REVOKE CREATE ON SCHEMA public FROM PUBLIC;
CREATE SCHEMA sqlscan AUTHORIZATION sqlscan_app;
```

Создайте x64 DSN и укажите его в **Приложение → Настройки базы данных…**. При подключении EXE автоматически выполнит встроенные скрипты схемы и обновления. Те же скрипты можно выполнить вручную из корня репозитория.

```powershell
$env:PGCLIENTENCODING = 'UTF8'
psql -X -h localhost -U sqlscan_app -d sqlscan -v ON_ERROR_STOP=1 -f db/schema.sql -f db/upgrade_2.sql
```

## Исходная версия 1.0


### Возможности

- Ввод текста вручную или загрузка из файла (до 2 МБ)
- 18 паттернов SQL-инъекций с весами от 1 до 5
- Цветовой градиент результата: зелёный → жёлтый → красный
- Подсветка опасных фрагментов в нормализованной строке
- Сохранение отчёта в файл UTF-8
- Динамическое изменение размера окна

### Как работает детектор

1. Входная строка **нормализуется**: приводится к нижнему регистру, несколько пробелов схлопываются в один
2. По нормализованной строке ищутся все **паттерны** из таблицы правил
3. За каждое вхождение к сумме прибавляется **вес** паттерна
4. Если найден хотя бы один паттерн с пометкой «высокий риск» или сумма весов ≥ 5 — строка считается **подозрительной**

### Таблица паттернов

| Паттерн | Вес | Высокий риск |
|---------|-----|--------------|
| `' or` | 3 | да |
| `" or` | 3 | да |
| `or 1=1` | 4 | да |
| `1=1` | 2 | нет |
| `;` | 1 | нет |
| `--` | 3 | да |
| `/*` | 2 | нет |
| `*/` | 2 | нет |
| `;--` | 4 | да |
| `union select` | 5 | да |
| `sleep(` | 4 | да |
| `benchmark(` | 4 | да |
| `xp_cmdshell` | 5 | да |
| `information_schema` | 3 | нет |
| `drop table` | 5 | да |
| `insert into` | 3 | нет |
| `update set` | 3 | нет |
| `delete from` | 3 | нет |

В версии 2.0 эти 18 записей используются для начального заполнения базы и автономной работы.

### Требования

- Windows 10 / 11
- Visual Studio 2022 (с компонентом «Разработка классических приложений на C++» и поддержкой MFC)
- Windows SDK (устанавливается вместе с Visual Studio)

### Сборка

1. Открыть `SqlScan.slnx` в Visual Studio
2. Выбрать конфигурацию `Debug` или `Release`, платформу `x64`
3. `Build → Build Solution` (или `Ctrl+Shift+B`)
4. Готовый `.exe` находится в папке `x64\Debug\` или `x64\Release\`
