# SqlScan 2.0.4

SqlScan проверяет текст и журналы на признаки SQL-инъекций. Для каждой подозрительной строки можно посмотреть совпадения, их вес и итоговый балл. Анализ работает локально в Windows x64, в том числе без подключения к интернету.

Версию 2.0.4 проверили по рабочей спецификации и контрольным примерам первой версии. Протокол содержит результаты испытаний загрузки файлов, работы с PostgreSQL и сравнения с опубликованной сборкой. [Результаты приёмки 2.0.4](docs/VERIFICATION-2.0.4.md)

**[Скачать установщик опубликованной 2.0.3](https://github.com/Zyared/SqlScan/releases/download/v2.0.3/SqlScan-2.0.3-x64.msi)** · **[ZIP версии 2.0.3 с тестами](https://github.com/Zyared/SqlScan/releases/download/v2.0.3/SqlScan-2.0.3-review.zip)** · [Протокол и контрольные суммы файлов](https://github.com/Zyared/SqlScan/releases/tag/v2.0.3)

## Первый запуск

1. Установите MSI для текущего пользователя и откройте **SqlScan** из меню «Пуск». Если выбрали ZIP, распакуйте его и запустите `SqlScan-Local.cmd`. При первом запуске программа подготовит локальную базу для журнала и редактируемых сигнатур.
2. На вкладке **Проверка** откройте `examples/demo.log` из комплекта и нажмите **Проверить**. В отчёте указаны номер строки, сработавшие правила и их вес.
3. Для разовой проверки без базы запустите `SqlScan.exe` напрямую. Доступны 18 встроенных правил и экспорт отчёта. Для сохранения истории используется PostgreSQL через ODBC. [Руководство пользователя](docs/USER_GUIDE.md)

Таблица показывает изменение между 2.0.2 и 2.0.3. Версия 2.0.4 прошла отдельное построчное сравнение с 2.0.3. Полнота показывает, какую долю размеченных атак обнаружил SqlScan. Ложная тревога означает, что программа пометила запись с нормальной меткой.

В группе из 1 740 ранее пропущенных атак с вложенными запросами обнаружены ещё **415**, остаются **1 325**. При построчном сравнении на Kaggle и HttpParams все прежние верные обнаружения сохранились, новых ложных тревог было **0**. Обе версии пропустили без тревоги все 451 обычную запись Kaggle с вложенным запросом. На отдельном наборе из 72 исполнимых SQL-запросов обе ошиблись на тех же шести. ## Как перепроверить результат

- **Баллы отдельной строки.** Запустите `Check-Scores.cmd`. Независимый расчёт сверит вывод программы на 51 контрольном примере и 1 000 заново сгенерированных входах, затем откроет HTML-отчёт. [Методика проверки баллов](docs/TRUST.md)
- **Работа программы.** Запустите `Recheck.cmd` из распакованного комплекта. Сценарий проверит целостность файлов, создаст временную базу и запишет результаты испытаний. [Матрица требований и испытаний](docs/VERIFICATION.md)
- **Качество на открытых данных.** Kaggle — площадка, где опубликован один из размеченных наборов. Первый вызов ниже загружает тестовые данные и сверяет их хеши. Второй повторяет измерение с готовым кэшем при отключённой загрузке. При неполном кэше он завершится с ошибкой. [Результаты по пяти источникам](benchmark/results/release-quality.json)

```powershell
.\Recheck.cmd -Quality -Cache D:\SqlScan-test-data
.\Recheck.cmd -Quality -Offline -Cache D:\SqlScan-test-data
```

## Возможности

| Вкладка | Действия |
|---|---|
| Проверка | Ручной ввод или файл, построчная оценка, нормализация, категории, четыре уровня риска, цветная подсветка, экспорт TXT/CSV/HTML |
| Журнал | Поиск и фильтры, сортировка, страницы по 50 записей, просмотр и экспорт архивного отчёта или выборки, удаление проверки |
| Сигнатуры | Добавление, редактирование, отключение и удаление, восемь категорий, применение изменений при следующей проверке |
| Статистика | Число и доля подозрительных проверок, диаграмма по дням и десять самых частых сигнатур |

При подключении к базе приложение сохраняет проверку и совпадения в одной транзакции. Для файла с уже известным SHA-256 можно открыть прошлый отчёт. Пакетный режим `--batch` выдаёт CSV с предсказаниями для размеченных данных.

## Сборка из исходников

Анализатор написан на C++20 и использует стандартную библиотеку C++. Для интерфейса нужны MFC и Win32, для работы с PostgreSQL — ODBC. Python используется в инструментах сборки и испытаний. [Архитектура и зависимости](docs/ARCHITECTURE.md)

Откройте `SqlScan.slnx` в Visual Studio 2026 с MSVC v145, MFC и Windows SDK и соберите конфигурацию `Release | x64`. В x64 Developer PowerShell сборку и тесты можно запустить командами ниже.

```powershell
.\build-release.ps1
.\tests\run.ps1
python tests/batch_smoke.py x64/Release/SqlScan.exe
```

Для тестов с базой укажите `SQLSCAN_TEST_CONNECTION` для отдельной тестовой базы. Для разработки GUI-тестов используются pywinauto и pywin32. Установщик из готового комплекта собирает Python 3.11+ с WiX 3.14.1.

```powershell
python deploy/build_installer.py <комплект> <каталог-WiX> SqlScan-2.0.4-x64.msi
```

## Внешняя база PostgreSQL

Для собственной базы установите PostgreSQL и 64-разрядный драйвер psqlODBC Unicode. [PostgreSQL для Windows](https://www.postgresql.org/download/windows/) · [psqlODBC](https://odbc.postgresql.org/).

Пример подготовки отдельной базы администратором через `psql`:

```sql
CREATE ROLE sqlscan_app LOGIN;
\password sqlscan_app
CREATE DATABASE sqlscan ENCODING 'UTF8' TEMPLATE template0;
\connect sqlscan
REVOKE CREATE ON SCHEMA public FROM PUBLIC;
CREATE SCHEMA sqlscan AUTHORIZATION sqlscan_app;
```

Создайте x64 DSN и укажите его в **Приложение → Настройки базы данных…**. При подключении EXE автоматически выполнит встроенные скрипты схемы и обновления. Те же скрипты можно выполнить вручную из корня репозитория.

```powershell
$env:PGCLIENTENCODING = 'UTF8'
psql -X -h localhost -U sqlscan_app -d sqlscan -v ON_ERROR_STOP=1 -f db/schema.sql -f db/upgrade_2.sql
```
