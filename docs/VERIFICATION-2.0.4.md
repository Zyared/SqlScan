# Приёмка SqlScan 2.0.4 для Windows x64

26 ноября 2026 года. Программу проверяли по [рабочей спецификации SqlScan 2.0](TZ_SqlScan_2.0.md). На момент испытаний её копии в репозитории и в каталоге курсовой побайтно совпадали. Индивидуальное задание первой версии использовали для проверки ввода, оценки и отображения. На этом этапе существовала пояснительная записка к первой версии, а оформление новой было отложено.

## Результат по пунктам

| Требование | Что проверено |
|---|---|
| §1–2. Перенос функций 1.0 и цель версии 2 | Пять исходных примеров дали те же баллы и вердикты, что исполняемый эталон 1.0. При работе с БД новая проверка доступна из журнала после повторного открытия. |
| §3.1. PostgreSQL и настройки | Кнопка «Проверить соединение» в GUI возвращает число активных правил при подключении по ODBC к отдельному PostgreSQL 17. Запись, чтение и очистка защищённой DPAPI настройки выполнены в изолированном разделе HKCU. |
| §3.2. Схема и история | На временной БД проверены шесть таблиц, восемь категорий, 18 исходных правил, CHECK/UNIQUE, внешние ключи и каскад удаления. Изменение параметров сигнатуры сохраняет исторические вес и вердикт. ER-модель и зависимости описаны в [архитектуре](ARCHITECTURE.md). |
| §3.3.1. Редактор | Нативный тест и GUI проверяют добавление, нормализацию, включение, отключение и удаление правил. Повторный анализ подхватывает изменение без перезапуска. Ограничения длины, веса и дубликатов действуют в приложении и БД. |
| §3.3.2. Автосохранение | Сводка и совпадения записываются в одной транзакции. Ошибка внешнего ключа откатывает запись. В отчёте с 16 421 совпадением проверены количество деталей и последние координаты за пределом буфера предпросмотра. |
| §3.3.3. Журнал | Проверены совместные фильтры, поиск, сортировка, смещение, страница из 50 строк, открытие и удаление. Уровни отсортированы от низкого до критического в обоих направлениях. Архив восстанавливает оценку каждой строки по сохранённым данным. Для старых неполных записей программа показывает, что построчная оценка недоступна. |
| §3.3.4–3.3.6. Повторные файлы, автономность, инициализация | Повторное открытие тех же байтов предлагает предыдущий отчёт по SHA-256. Остановка PostgreSQL во время работы окна переводит его в автономный режим. После запуска сервера следующая проверка сохраняется. Чистая установка схемы и её обновление выполняются в одной транзакции. Четыре параллельных подключения создали один комплект начальных данных. |
| §3.4. Безопасность и состав архива | Проверены права отдельной роли и сохранение контрольной строки как данных через ODBC. Переменные значения передаются связанными параметрами. В БД нет поля полного исходного файла. Короткий контекст совпадения может включать короткую строку целиком. |
| §4.1–4.3. Строки, нормализация, категории, риск | У лог-файла каждая полная строка проверяется независимо. Для многострочного образца пакетного режима сохранена общая граница записи. Проверены три примера нормализации из §6.2, координаты, четыре уровня риска и воспроизведение совпадений после 16 384 деталей. |
| §4.4. Статистика | Доля подозрительных проверок и диаграмма по дням проверены в окне приложения. Топ-10 считает срабатывания по ID сигнатуры. Тест переименовал правило и проверил, что его срабатывания остались в одной строке. |
| §4.5. Экспорт | Проверены текущий отчёт, архив и отфильтрованная выборка. У текстовых экспортов проверены байты BOM и корректность UTF-8. В CSV и HTML проверены поля, экранирование и строковые оценки. Текущий отчёт записывается в выходной поток. Неудачная операция оставляет прежний файл целым. |
| §4.6 и главное окно | Обе группы Microsoft Native Unit Test выполнены через VSTest x64. Тесты настоящего окна проверили четыре вкладки, меню, состояние БД, совпадения и отчёты. Измерения качества приведены ниже. |
| §5. Стек и архитектура | Сборка Release x64 выполнена MSVC с C++20 и MFC. Движок не включает заголовки MFC. Правила поступают через `IRuleSource`, доступ к данным изолирован в репозиториях. Дескрипторы ODBC освобождаются по RAII. В продукте используются Win32, GDI, CNG, DPAPI и ODBC. Таблица импорта EXE содержит системные DLL Windows. Ядро не использует `std::regex` и .NET. Сторонние детекторы и Python находятся в средствах перепроверки. |
| §5. Надёжность и быстродействие | Ошибки подключения, отключение/возврат БД, повреждённые числовые настройки, усечение UTF-8 и сохранность результата при ошибке CSV проверены отдельно. В повторном прогоне 512 КиБ обработаны за 1 мс, плотный текст — за 7 мс, 1 000 совпадений сохранены за 17 мс. Три открытия журнала из 10 000 записей заняли 78,9, 73,9 и 77,5 мс. Пределы ТЗ соответственно 100 мс, 1 с и 1 с. Замеры относятся к одному ПК. |
| §5. Развёртывание | Для локального запуска предусмотрены EXE, схема, инструкция подключения DSN и переносной комплект. Для автономного анализа журналов интернет не требуется. Для воспроизведения открытых корпусов без интернета нужен заранее заполненный кэш. [Руководство](USER_GUIDE.md) |
| §6.2. Испытания | Выполнены пять регрессий 1.0, примеры нормализации, проверки БД, отката, отказа сервера и нагруженного журнала. Независимый расчёт совпал с программой на 1 051 входе. Каждая из четырёх намеренных подмен результата была отклонена. |
| §7.1–7.2. Данные и эталоны | Сравнение выполнено без сетевой загрузки по пяти закреплённым источникам с проверкой хешей. На тех же входах запущены исходное ядро 1.0, SqlScan, libinjection и OWASP CRS. [Версии и суммы наборов](../benchmark/sources.json) |
| §7.3–7.5. Метрики, воспроизводимость, ошибки | Повторены матрицы ошибок, precision, recall, FPR, F1 и тематические срезы. На входах с неизвестным типом аномалии полнота SQL-инъекций не вычисляется. Разбор известных пропусков и ложных тревог сохраняет силу по результатам попарного сравнения. [Методика](TRUST.md) · [Разбор ошибок](DETECTION-2.0.3.md) |

## Как повторить

В каталоге комплекта Windows x64 выполните команды ниже. Первая запускает независимую сверку баллов. Вторая использует уже заполненный кэш и временную БД. Чтобы добавить две группы VSTest, задайте переменную `SQLSCAN_VSTEST` с путём к `vstest.console.exe`. Для взаимодействия с окном нужен интерактивный сеанс Windows.

```powershell
.\Check-Scores.cmd
.\Recheck.cmd -Quality -Offline -Cache D:\SqlScan-test-data
```

Сценарий сохраняет протокол `checks.txt` и агрегаты `scores.json`, `ordinary-sql.json`, `quality.json`, `paired.json`, `refactor.json`. Имя созданного каталога выводится в консоль. Хеш проверяемого EXE сверяется отдельно от результатов, включая баллы и характеристики эталонных движков.

## Границы приёмки

В окне программы проверены загрузка ровно 2 МиБ, отказ на 2 МиБ + 1 байт с сохранением предыдущего результата и одинаковая обработка текста в Windows-1251 и UTF-8 с BOM. По умолчанию приложение открывает файлы до 2 МиБ и анализирует первые 512 КиБ. При усечении в отчёте видны обработанный и исходный размеры. Доступный для просмотра фрагмент большого файла защищён от случайного редактирования. Исходный текст для проверки хранится отдельно от предпросмотра.

Фоновая очередь с отменой (§4.7), алгоритм Ахо — Корасик (§4.8), применение белого списка к оценке (§4.9) и пользовательские роли (§4.10) обозначены в ТЗ как факультативные. Таблица белого списка входит в схему. §6.1 относится к новой пояснительной записке, §6.3 — к календарному графику курсовой. Приёмка программы и готовность новой записки учитываются отдельно.
