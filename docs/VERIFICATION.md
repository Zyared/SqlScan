# Приёмка SqlScan 2.0.3 для Windows x64

19 ноября 2026 года. Результаты относятся к готовому `SqlScan.exe` с SHA-256 `83e1fa755f386656651b821ddd7348045dfe4df9c8d579d4b88f0f6033c5b9e0`. Сверены ТЗ от 30.10.2026 из Git и его версия в Obsidian. Таблицы ниже покрывают обязательный объём. Точные контрольные суммы компонентов приведены в `SHA256SUMS` готового комплекта. Пояснительная записка отложена по решению автора. Настоящая поставка предназначена для проверки программы.

## Как перепроверить

1. Установите MSI для своего пользователя или распакуйте весь ZIP в обычный каталог. Для работы с приложением запустите `SqlScan-Local.cmd`; личный журнал хранится в профиле пользователя. Для изолированной перепроверки дважды щёлкните `Recheck.cmd`. Требуется интерактивный сеанс Windows x64. Будут открываться и закрываться окна тестового экземпляра.
2. Перепроверка сверяет файлы с описью, разворачивает временную БД, выполняет SQL-, нативные, пакетные и GUI-тесты. Распакованные PostgreSQL, psqlODBC, Python x64 и библиотеки автоматизации включены. Visual Studio для этого режима не требуется. Сценарий останавливает тестовый сервер и очищает свою тестовую БД.
3. Для воспроизведения научного эксперимента из каталога комплекта запустите `Recheck.cmd -Quality`. При первом прогоне нужны пять открытых источников через HTTPS. Опция `-Cache "D:\SqlScan-test-data"` сохраняет проверенные данные для последующих автономных прогонов. Все входы интерпретируются как текст. Запросы к внешним проверяемым системам не выполняются.
4. Каждый запуск пишет `checks.txt`, а при выборе `-Quality` также `quality.json` и `paired.json` в новый подкаталог `%LOCALAPPDATA%\SqlScan2\Checks`. Путь напечатан при завершении. Код возврата 0 и строка PASS означают успешный прогон. Сравнение качества требует совпадения итогового JSON с поставленным протоколом. Предыдущие проверки сохраняются.
5. Исходники включены в `source`. Для Test Explorer предусмотрен проект NativeTests. Переменная `SQLSCAN_VSTEST` может указывать на установленный `vstest.console.exe`, чтобы общий сценарий дополнительно выполнил поставленную нативную DLL. Для сборки приложения см. README. Для короткой демонстрации преподавателю запустите `Check-Scores.cmd`. [Как проверить баллы и точность](TRUST.md).

| §3.3.6. Инициализация и обновление | В чистой БД выполнены скрипты схемы; отдельная запись из первой схемы пережила обновление. Повторная инициализация сохраняет изменённые правила и настройки. |

**Критерий F1.** На HttpParams F1 исходного ядра равен 0,718385, у версии 2.0.3 он равен 0,773351. На Kaggle результат вырос с 0,547043 у 1.0 до 0,694140 у 2.0.3. Полнота 2.0.3 на этих наборах — 63,06 % и 55,94 %. [Попарное сравнение с 2.0.2](DETECTION-2.0.3.md). На 36 000 нормальных запросов CSIC получено 0 ложных тревог SqlScan. На смешанном разделе — 2 032 срабатывания. Уровень полноты для этого раздела определить по опубликованным меткам нельзя.

**Условия применения.** Результат помогает отобрать строки для ручной проверки. Высокий процент пропусков у отдельных классов ограничивает самостоятельное использование. Скорость измерена на одном Windows x64 ПК. Отдельные факультативные функции §4.7–4.10 не входили в обязательную поставку.
