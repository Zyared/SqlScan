## Разбор исходных 1 740 пропусков

Обе версии получили исходные строки в прежнем порядке. Определение группы и версия 2.0.2 зафиксированы предыдущим протоколом и хешем исполняемого файла. Внутри группы проверяющий сценарий различает формы в порядке таблицы. Каждая запись учтена один раз. Формы определены по наблюдаемому синтаксису. Исходная разметка Kaggle сообщает только норму или атаку.

Набор и агрегаты контрольной части уже просматривались при разработке, поэтому эти цифры описывают воспроизводимую регрессию на известном корпусе. Для оценки переноса на другую среду нужен новый размеченный журнал.

## Как принимается решение

Движок рассматривает совместные признаки в отдельном коротком значении параметра. Первый вариант учитывает форму начала значения, логическое продолжение и вложенное ветвление с числовыми константами. Второй учитывает сравнение с подсчётом строк по нескольким повторениям одного источника. Обычный запрос с агрегатом, обращение к столбцу и конструкция EXISTS сами по себе не дают новой тревоги.

Проверка включается для отдельной строки с допустимым завершающим переводом строки, длиной до 1 024 нормализованных байт, если прежние сигнатуры дали ноль совпадений и ввод не был усечён. Сохранены 18 настроек исходных правил. Оба варианта используют вес и флаг риска логического правила `or 1=1`; его отключение отключает и варианты. В отчёт и архив записывается название реально найденного структурного признака. Поэтому начисление можно проверить и после редактирования настроек.

## Контроль обычного SQL

- В Kaggle есть **451** запись с нормальной меткой и вложенным SELECT. Ни одна не вызвала тревоги в обеих версиях.
- Дополнительно проверены **24 семейства обычных запросов в трёх вариантах записи**. Все 72 запроса реально выполнились в небольшой базе SQLite только для чтения. Среди них коррелированные подзапросы, CTE, оконные функции, числовые условия, повтор таблицы, комментарии и многострочные отчёты. Обе версии выдали **6 ложных тревог** на запросах с объединением результатов и на комментариях. Остальные 66 остались без тревоги. SQLite используется только этим тестом.
- На 36 000 нормальных запросов CSIC тревог у обеих версий нет. По всем 102 863 записям пяти источников не появилось новых ложных тревог и не потеряно прежних истинных срабатываний на размеченных строках. На части CSIC со смешанными аномалиями нет отдельных меток SQL-инъекций.

## Повтор

`Recheck.cmd -Quality -Offline -Cache D:\SqlScan-test-data` выполняет проверки из заранее заполненного кэша. При отсутствии файла сценарий сообщает, какого набора не хватает, до обращения к сети. Результаты сохраняются в отдельном каталоге проверок. Обычные SQL-запросы проверяются и при простом запуске `Recheck.cmd`.
